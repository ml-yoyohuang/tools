# 餅乾帝國

受 Cookie Clicker 啟發的純網頁放置遊戲：從手動點擊開始，逐步建立自動生產帝國。原生 HTML / CSS / JavaScript，**零執行時依賴**、沒有建置流程、不連外部 CDN 或遠端字型、**沒有任何音效或音訊資源**。

名稱、描述、圖片與數值全部原創，沒有複製原作的程式或素材。

目前所有圖片都是本地產生的 SVG 占位圖，可直接替換（見「換圖指南」）。

## 啟動方式

請以 http 開啟（瀏覽器對 `file://` 下的本機資源有額外限制）。在專案根目錄：

```bash
python -m http.server 8767 --bind 127.0.0.1
```

接著開 <http://127.0.0.1:8767/game-bakery/>。

## 部署

整個資料夾就是可部署的靜態網站，複製到任何靜態主機即可。所有資源都是相對路徑，放在子目錄也能運作。

## 計算規則

**加成結算順序**（明確區分相加與相乘，且不會循環）：

```
單一設備每秒產量
  = baseCps
  × Π(升級的設備倍率、階層倍率)        ← 相乘
  × Π(設定表中已達成的數量里程碑)       ← 相乘
  × (1 + Σ(搭配加成、升級里程碑))       ← 先相加再乘

未含限時效果的總產量 baseCps = Σ(各設備產量) × Π(全局倍率)
含限時效果的產量      cps     = baseCps × 限時倍率

點擊收益 = (點擊基礎 × Π(點擊倍率) × (1 + Σ(設備回饋)) + 產量回饋) × 連擊 × 限時倍率
```

**所有搭配一律讀「設備數量」，絕不讀其他設備的最終產量**，因此沒有循環計算的可能。千層壓模的「產量回饋」也只讀未含限時效果的 `baseCps`。

**價格**：`cost(n) = baseCost × growth^n`，`growth` 預設 1.15。批量價格用等比級數封閉解計算（不是逐項累加），最大購買數量先用對數求解再逐步修正到剛好買得起。折扣只乘在結帳金額上，不改變 `n`。

**餘額保護**：扣款前檢查 `cookies >= cost`，不足就完全不扣；餘額永遠夾在 0 以上。累積製作量只增不減，花費不會讓它下降。

## 時間與收益政策

每次結算都會把 `lastSettle` 推進到現在，**同一段時間只會被結算一次**，所以不可能靠切換分頁重複領取。判斷方式只看「距離上次結算多久」，不管是切到背景、關閉頁面還是當機：

| 間隔 | 處理方式 |
| --- | --- |
| ≤ 60 秒 | 視為正常遊玩，100% 結算，**含**限時倍率。切成 250ms 小片段，讓限時效果能準確在中途到期 |
| > 60 秒 | 離線結算：**50%** 效率、最多 **8 小時**，**不含**任何限時倍率 |

因為一般使用 `setInterval` 在背景分頁仍會執行（只是被節流），所以切到背景通常落在 60 秒內，拿到的是 100%；真正關掉頁面才會走離線政策。

其他規則：系統時間倒退時不給負收益、也不當成離線；離線期間不累積可點擊事件（回來後重新排程）；過期的限時效果在結算時一併清除。

## 換圖指南

1. 圖片都在 `assets/`，檔名對應設定表：
   - **主餅乾序列** `cookie-01.webp` ～ `cookie-05.webp`（真實照片，見下方）
   - 黃金餅乾 `cookie-golden.svg`
   - 設備 `building-01.svg` ～ `building-08.svg`
   - 道具 `item-01.svg` ～ `item-04.svg`
   - 升級 `upgrade-<升級ID>.svg`
2. 直接覆蓋同名檔案即可，SVG 或 PNG 都行，支援透明背景。
3. 要換路徑或檔名，改 `js/config.js` 的 `image` 欄位（設備／道具）或 `js/content.js`（升級）。
4. 圖片以 `object-fit: contain` 呈現，會自動保持長寬比並置中。
5. 任何一張載入失敗，該項目自動改用色塊與名稱縮寫，遊戲照常運作，畫面上會出現提示。
6. 新增內容後重新產生占位圖：`node tools/make-dummy-art.js`（這個腳本不再產生主餅乾）。

### 主餅乾序列

主餅乾是 5 張真實照片影格，**每點擊一次換下一張，循環播放**（第 0 次用 01、第 4 次用 05、第 5 次回到 01）。
影格數量不是寫死的，`js/config.js` 的 `COOKIE_FRAMES` 放幾張就循環幾張。

要換成另一組序列，把去背原圖放進一個資料夾後執行：

```bash
pip install pillow numpy          # 只有準備美術資源時需要，遊戲本身零依賴
python tools/prepare-cookie-frames.py <原圖資料夾>
```

這個腳本會：

- **修掉透明區滲色**：把透明與半透明像素的 RGB 填成鄰近的餅乾色。
  去背輸出的透明區常殘留白色或深色雜訊，縮圖取樣時會在邊緣滲出白邊或黑點，深色主題下特別明顯。
- **統一對位**：以「實心像素重心」與「涵蓋 95% 質量的半徑」為基準，把每張縮放平移到同一個正方畫布，
  播放時才不會上下跳或忽大忽小。
- **縮圖壓縮**：輸出 384×384 WebP，每張約 40KB（原圖每張 2.3MB）。

可調參數在腳本頂端：`OUT_SIZE`（輸出邊長）、`TARGET_RADIUS`（餅乾在畫布中的等效半徑，留邊給碎屑）、
`WEBP_QUALITY`。檔名會依排序編號成 `cookie-01` 起跳，`__` 開頭的檔案會被忽略（方便放備份）。
改完檔案數量記得同步更新 `COOKIE_FRAMES`。

> SVG 是嚴格的 XML，同一元素出現重複屬性會整張解析失敗。

## 參數調整指南

全部集中在 `js/config.js` 的 `BALANCE`、`BUILDINGS`、`ITEMS` 與 `js/content.js` 的 `UPGRADES`、`ACHIEVEMENTS`：

| 位置 | 用途 |
| --- | --- |
| `BALANCE.clickBase` | 每次點擊的基礎收益 |
| `BALANCE.defaultGrowth` | 價格成長率 |
| `BALANCE.offline` | 離線效率、時數上限、寬限秒數 |
| `BALANCE.buffMaxSeconds` | 三種限時效果各自的累積上限 |
| `BALANCE.golden` | 事件出現間隔、壽命、獎勵權重 |
| `BALANCE.combo` | 連擊的累積速度、上限與衰退 |
| `BALANCE.autoSaveSeconds` | 自動存檔間隔 |
| `BUILDINGS[].baseCost / baseCps / growth / revealAt / milestones` | 單一設備的價格、產量、揭曉門檻與數量里程碑 |
| `UPGRADES[].cost / req / effect` | 升級價格、解鎖條件與效果 |

升級效果支援的型別：`clickMult`、`clickFromCps`、`clickFromBuilding`、`lucky`、`combo`、`buildingMult`、`buildingTierMult`、`buildingMilestone`、`synergyCount`、`synergyTiers`、`globalMult`、`globalIfAll`、`goldenBoost`、`buffDuration`。新增升級只要填設定，不需要改計算程式。

- **4 種道具**：如上表。
- **32 個成就**：涵蓋累積製作、設備數量、點擊、升級數與組合，其中 18 個附帶一次性道具獎勵。
- **黃金餅乾事件**：每 150～360 秒出現一次、存在 14 秒，點到可得餅乾或道具。不點也不影響正常發展。

## 可及性與介面

- 分數、產量、點擊收益、下一個目標都是 HTML 文字，不依賴 hover 才能看到效果。
- 持續變動的數字**不放在** `aria-live` 區域，只有成就、道具、離線結算等重要事件會朗讀。
- 所有操作都能用鍵盤完成，分頁可用左右方向鍵切換；對話框使用原生 `<dialog>` 管理焦點，關閉後焦點回到原按鈕。
- 大餅乾只綁 `click`，不另外綁 touch 事件，避免一次操作算成兩次點擊。
- 浮動數字有數量上限（18 個），快速點擊不會無限累積 DOM 節點。
- 支援淺色／深色／跟隨系統，以及完整／減少／跟隨系統的動畫設定（減少動畫時關閉浮動數字）。
- 窄螢幕無水平捲軸，按鈕高度至少 40–44px，並考慮手機安全區域。
