# 疊色印章集章｜設計方向文件

> 每次開始新的工作前，請先讀完這份文件。所有實作都要符合這裡的方向。
> 文件裡的每一條要求，背後都有一個「為什麼」。遇到文件沒寫到的情況時，請回到「為什麼」去判斷，而不是選最省事的做法。

---

## 0. 先認識這個專案的主人

這是一個「做好玩」的個人專案。它延續了我們上一個成功的作品 INK INK｜印印（網頁版絹印體驗），那次的成功經驗，就是這次的基礎：

- **手感**：操作要有「真的在做這件事」的身體感，而不是點按鈕。
- **不完美是樂趣**：雜訊、失真、錯位、飛白，都是作品的一部分。
- **每個人的成品都不一樣**：而且差異來自使用者自己的手，不是隨機套上的濾鏡。

這次要再往前一步：**要很有體驗感、遊戲感，要有身歷其境的活動臨場感。不能只是一般的網站排版和平鋪直述的文字。**

這位主人喜歡「先做做看，玩了再調」。所以請把可能需要調整的東西做成容易修改的設定，例如角度範圍、墨量、評語門檻、旋轉功能的開關。不要寫死在程式各處。

## 1. 專案一句話

一個網頁版的「重ね捺しスタンプ」（疊色印章）集章活動：同一幅圖拆成三個顏色，分在三個集章點，每站蓋一個顏色。集滿三站，三層疊在一起，就完成一整幅屬於你的集章明信片。

專案名稱未定。

## 2. 核心原則

1. **介面即道具。**
   畫面上盡量不出現一般網站的按鈕和說明文字，所有操作都透過「東西」來完成：集章卡、印章、印台、郵戳、郵筒。需要說明的時候，由現場的「人」（站務員）用台詞說出來，不寫成說明文字。
2. **每個關鍵時刻都要有「醞釀、動作、揭曉」的節奏。**
   領卡、到站、蓋章、完成，都不是瞬間切換，而是有鋪陳、有動作、有揭曉的小儀式。
3. **錯位是樂趣，但不能變成挫折。**
   對位完全由使用者負責，系統不會自動吸附或修正。不過要給足夠清楚的輔助，讓人可以專心對位；結果也一律用正面的方式回饋。
4. **每一張明信片都獨一無二。**
   不一樣來自三件事：使用者的手（位置、角度、施力、沾墨）、走的順序（先蓋哪個顏色），以及蓋章的時間地點（日期戳）。
5. **聲音和動態是臨場感的主要來源。**
   不靠寫實的 3D 或擬真畫面，靠的是節奏、聲音、動態和角色。

## 3. 世界觀與角色

### 3.1 站務員

- 一位原創角色，負責迎接、說明、加油、慶祝。他是這場活動的「人味」來源。
- **個性**：熱情、有點愛大驚小怪、很會稱讚人，偶爾冷笑話。
- **說話方式**：
  - 對話框一句一句跳出來，像遊戲的劇情對話。點一下就跳到下一句。
  - 每句都很短，口語，可以用驚嘆號和顏文字。
- **禁止**：模仿任何現有的角色、吉祥物或品牌形象。

**台詞範例**（語氣參考，可自由發揮）：
- 「歡迎光臨！你是今天的第一位客人……的其中一位！」
- 「來，這是你的集章卡。收好喔，弄丟了我會難過的。」
- 「印台要點幾下沾墨喔，太少會蓋得淡淡的～」
- 「你是從這一站開始的呀！好有個性的路線！」
- 「這一站已經蓋過囉！要不要去找下一站？」
- 「還差一站！我已經準備好拉炮了！」

### 3.2 活動會場的氛圍

- 熱鬧、明亮、有祭典或市集感。
- 布條、彩旗、站牌、櫃台、印台這些元素，用簡潔可愛的 2D 插畫風格呈現，不做 3D 或寫實。

## 4. 體驗腳本

### 第 0 幕：抵達會場（第一次進來）

1. 畫面不是首頁，而是活動入口。布條緩緩降下，彩旗飄動，伴隨熱鬧的環境音和一聲「歡迎光臨！」
2. 站務員出場，用對話框打招呼。
3. 站務員從櫃台拿出一張空白集章卡，滑到使用者面前。使用者要「親手」收下：往上滑，或長按收下。
4. 使用者在卡片上寫名字（可略過），卡片蓋上今天的日期戳。
5. 卡片背面印著「卡片編號」，也就是進度代碼（見第 8 節）。
6. 站務員說明玩法：「全部有三站，從哪一站開始都可以喔！」

### 第 1 幕：抵達某一站

1. 每個 QR Code 都帶著站號。掃描後先播放抵達動畫：站牌翻轉、站名浮現，伴隨到站鈴聲。
2. 每一站都有自己的主題色、站名和印章。站務員說一句這站專屬的台詞。
3. 順序不限。系統要記錄使用者到站的順序，也就是「路線」。
4. 如果還沒領集章卡就直接掃了站點，先跑一次簡短的第 0 幕，再進入這一站。
5. 如果這一站已經蓋過，就不能重蓋，避免蓋壞已完成的層。站務員會友善地提醒，並顯示已蓋好的卡片。（例外：還沒離開這一站之前，可以「補蓋」，見 5.7。）

### 第 2 幕：蓋章（核心玩法，詳見第 5 節）

依序是：沾墨、拿起印章、對位、施力蓋下、拿起揭曉、評語。

### 第 3 幕：盛大慶祝（蓋滿三章）

1. 第三章蓋下後，停頓約一秒。畫面全暗，只留聚光燈照著集章卡。
2. 鑼鼓聲響起，彩帶和墨水滴形狀的紙花一起噴發。
3. 站務員激動地跑出來，頒發一枚「完成章」，蓋在卡片角落。
4. 集章卡翻面，變成明信片背面：
   - 可以寫一句話
   - 蓋上郵戳，郵戳上有日期
   - 印出這張卡的路線，例如「2 → 3 → 1」
   - 印出三章各自的評語
5. 使用者把明信片投進郵筒，動畫結束後可以下載成圖片或分享。

### 回訪

- 使用者再次進來時，不要重新播放開場。
- 站務員會依照進度說話，例如：「歡迎回來！還差兩站喔」。
- 已完成的使用者回訪時，可以欣賞自己的明信片，或重新領一張新卡再玩一次。

## 5. 蓋章機制（最重要的部分）

### 5.1 沾墨

- 使用者把印章壓到印台上，點幾下沾墨。
- 點的次數決定墨量：
  - 太少：飛白、顏色淡
  - 剛好：飽滿
  - 太多：邊緣暈開、糊成一團
- 印台上要有視覺回饋，讓人看得出現在大概沾了多少墨。

### 5.2 對位

這一步和 INK INK 的「放下網框」一樣：完全由使用者自己移動、自己對準。不同的是，這次還要對準**角度**。

**移動與旋轉**
- **移動**：手指拖動印章。
- **旋轉**：
  - 主要方式：雙指旋轉，同時也可以拖動位置。
  - 備用方式：印章外圈有一個旋轉把手，單指拖著繞圈即可旋轉。給單手操作或不習慣雙指的人使用。
  - 桌機：拖動旋轉把手，或用滑鼠滾輪旋轉。
- **角度限制**：約正負 30 度，做成可調整的設定。
- **完全沒有自動吸附或自動修正。**

**殘影與輔助（讓人專心對位）**
- **落點殘影**：印章移到卡片上方時，下面顯示一個半透明的殘影，呈現「現在蓋下去會印在哪裡、長什麼樣子」。殘影要很清楚，這是避免挫折的關鍵。
- **聚焦**：對位時，已經蓋好的層稍微加深對比，畫面上其他裝飾淡化，讓整個畫面只剩下「我要對準的東西」。
- **十字對位標記**：負責「位置」。印章和卡片上都有。
- **正上方三角形**：負責「方向」。這是真實集章活動常用的設計。
  - 印章正上方有一個三角形，代表「這邊朝上」，旋轉時跟著轉。
  - 卡片上每個蓋章框的正上方，也印著一個淡淡的三角形。
  - 殘影裡也會顯示三角形。
- **接近回饋**：位置和角度越接近對準，殘影外框、十字和三角形就從灰色慢慢變亮。這只是回饋，不會吸附。
- **放大鏡**：手指按住時，旁邊浮出一個放大圓窗，顯示手指底下的細節，解決手指擋住畫面的問題。圓窗的位置要避開手指。
- **精細模式**：手指停住不動片刻，移動和旋轉就自動變慢、變細，方便最後微調。

**第一章**
- 第一章沒有前一層可以對，所以對著卡片上淡淡印著的「蓋章框」（含十字和三角形）蓋。
- 不論從哪一站開始，第一章都這樣處理。

### 5.3 施力蓋下

- **長按代表施力**：
  - 太短：墨淡、飛白多
  - 適中：最好
  - 太久：暈開
- 按住期間有視覺回饋，例如印章微微下沉、出現壓力圈。
- 按住時手指滑動，會造成拖影或雙重印。
- 蓋下的瞬間：畫面輕微震動，並播放「咚」的蓋章聲。Android 手機可以加上震動；iPhone 的網頁大多不支援震動，就用聲音和畫面晃動代替。

### 5.4 拿起揭曉

- 拿起印章的那一刻放慢動作，揭曉這一層的結果。

### 5.5 瑕疵

每一種瑕疵都要來自使用者的操作，而不是隨機套用。

| 操作 | 結果 |
|---|---|
| 沾墨太少 | 飛白、顏色淡 |
| 沾墨太多 | 邊緣暈開、糊塊 |
| 施力太短 | 印得不完整、飛白多 |
| 施力太久 | 暈開 |
| 按住時滑動 | 拖影、雙重印 |
| 位置偏 | 與其他層錯位 |
| 角度偏 | 與其他層產生角度差 |

另外，每一次蓋章都要帶著輕微的基礎質感，程度比照 INK INK 的「輕微手感」，接近 Risograph 印刷：邊緣微抖，有零星飛白。即使兩個人的操作一模一樣，結果也會有細微差異。

### 5.6 評語

蓋完後依照對位結果給評語。**每一種都是正面的**：

| 對位結果 | 評語範例 |
|---|---|
| 幾乎完美 | 「職人級對位！」 |
| 有點偏 | 「剛剛好的手作感」 |
| 歪很多 | 「大膽的藝術錯位！」 |

- 評語由站務員說出來，並記錄在卡片上，最後會印在明信片背面。
- 判定門檻做成可調整的設定。
- 第一章是對蓋章框，不是對前一層，但同樣給評語。

### 5.7 補蓋（次要流程）

就像蓋實體章時，看到墨太淺，會想再蓋一次、努力對準讓它接起來。

- **只能在離開這一站之前補蓋。** 蓋完後印章回到印台，想補蓋就再沾墨、照同樣流程蓋。換到別站（或之後再回來）就鎖定，避免蓋壞已完成的層。
- **次數上限做成設定**，預設每站最多補蓋 1 次（兩次疊起來）。
- **對位基準是這一站自己剛蓋的那一層**，不是其他層。重點是「接不接得起來」。
- 同色墨疊兩次，重疊處會變深；沒對準時會出現深色的邊，像真的補蓋過。
- 站務員只在第一次蓋得偏淡（沾墨太少或施力太短）時，提一句「要補蓋一下嗎？」。其他時候不主動提，補蓋是安靜存在的選項，不打擾主流程。
- 補蓋有自己的評語（例如「接得天衣無縫！」「補得好有味道～」「雙重印的藝術！」），一樣都是正面的。**這一站的正式評語仍是第一次蓋的那一句**，最後印在明信片背面。
- 路線只記錄到站順序，補蓋不算一站。

## 6. 疊色與成品

- 同一幅原創圖案拆成三個顏色層，每一站負責一層。
- **順序會影響結果**：墨水不要做成完全透明的相乘，而是帶有一定的遮蓋力。這樣「先藍後紅」和「先紅後藍」的結果就會不同，每個人走的路線都會留在作品上。混合的程度做成可調整的設定。
- 三層圖案的設計要讓錯位依然好看：每一層都有自己的完整形狀，不要讓某一層只有細線。
- 圖案必須是原創的，不模仿任何現有的角色、品牌或作品。

## 7. 站點與 QR Code

- 每個 QR Code 連到同一個網站，用網址參數帶入站號，例如 `?station=2`。
- **開發測試模式**：要能不用掃 QR Code 就切換站點，方便在電腦上測試。正式版本要能把這個模式關掉。
- 目前不做防作弊。這是自己做好玩的專案，將來如果拿到市集或展覽使用，再另外處理。

## 8. 進度與資料

- 進度存在使用者的瀏覽器裡，不做帳號和後端。
- 要存的內容：
  - 是否已領卡、名字、領卡日期
  - 每一站的蓋章結果：位置、角度、墨量、施力、評語、時間，以及重建畫面所需的資料（一站可能有多次蓋印：第一次加上補蓋，要依實際蓋印順序全部保存）
  - 路線順序
- **進度代碼要做成道具**：
  - 不要用彈出視窗叫人備份，而是印在集章卡背面，當作「卡片編號」，旁邊寫「遺失時請出示此編號」。
  - 輸入這組編號就能恢復進度。
- **未來會接 LINE（LIFF）**，讓進度跟著 LINE 帳號走。請讓儲存層和其他程式分開，方便之後替換。

## 9. 平台與技術

- **手機優先**：集章是拿著手機在現場走的活動。桌機也要能完整玩，方便測試和分享。
- 技術：HTML、CSS、JavaScript，搭配 Canvas 2D，不使用 3D。
- 觸控手勢要確實處理：雙指操作時要防止瀏覽器的頁面縮放和捲動。

## 10. 旋轉功能開關

- 旋轉是新嘗試，玩起來可能太難。主人已經說過，不好玩可能會拔掉。
- 所以所有跟旋轉有關的功能都要由同一個設定開關控制，包括：
  - 旋轉操作
  - 旋轉把手
  - 三角形方向回饋
  - 角度相關的瑕疵與評語
- 關掉之後，印章永遠是正的，其他功能照常運作。

## 11. 開發階段

1. **階段一：蓋章原型。** 驗證沾墨、對位（含旋轉）、施力、揭曉、瑕疵、評語好不好玩，以及三層疊起來的效果。
2. **階段二：整理架構。** 拆成模組，建立儲存層和設定檔。
3. **階段三：活動體驗。** 第 0 幕入口與領卡、站務員與對話系統、到站動畫、回訪、進度代碼、第 3 幕慶祝、明信片背面與下載。
4. **階段四：打磨。** 加入音效、調整手感參數、處理桌機版。
5. **之後再說**：接上 LINE。

## 12. 禁止與避免

- 一般網站的排版：一排按鈕、表單、長段說明文字、制式的彈出視窗。
- 平鋪直述的說明文字。需要說明時，交給站務員用台詞說。
- 自動吸附或自動修正對位。
- 讓使用者覺得自己「失敗」的回饋。
- 模仿現有的角色、品牌、商標或作品。
- 文件沒有提到的新功能。若想加，先提出來討論。
