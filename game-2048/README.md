# 2048

純前端的 2048 遊戲，是 DevToolbox 工具集的一部分。原生 HTML / CSS / JavaScript，沒有任何執行時依賴、沒有建置流程、不連外部 CDN 或遠端字型，開啟 `index.html` 就能玩。

## 啟動方式

直接開檔即可：

```bash
start index.html
```

或在專案根目錄起一個靜態伺服器（測試頁與遊戲都能從瀏覽器開啟）：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

接著開 <http://127.0.0.1:8765/game-2048/>。

## 部署

整個資料夾就是可部署的靜態網站，複製到任何靜態主機（GitHub Pages、Netlify、Nginx…）即可，不需要後端、帳號或付費服務。所有資源都是相對路徑，放在子目錄也能運作。

## 檔案結構

```
game-2048/
├── index.html          遊戲頁面（語意化結構 + 對話框）
├── css/style.css       全部樣式與主題變數
├── js/
│   ├── engine.js       規則引擎：壓縮、合併、計分、勝負判斷（純邏輯，不碰 DOM）
│   ├── session.js      對局狀態：最高分與悔棋紀錄（純邏輯）
│   ├── storage.js      localStorage 存取與存檔驗證
│   ├── settings.js     外觀與動畫偏好
│   ├── render.js       方塊 DOM 與動畫
│   ├── input.js        鍵盤、觸控手勢、方向按鈕
│   └── app.js          組裝層：輸入佇列、對話框、提示訊息
├── tests/
│   ├── suite.js        測試案例（Node 與瀏覽器共用同一份）
│   ├── run-node.js     Node 執行器
│   └── index.html      瀏覽器執行器
└── README.md
```

各層以全域物件串接（`Game2048Engine`、`Game2048Session`…），因此不需要打包工具，也能直接用 `file://` 開啟。`engine.js` 與 `session.js` 同時支援 `module.exports`，所以同一份程式碼可以在 Node 裡測試。

## 玩法與規則

- 預設 4×4，開局在不同空格生成兩個方塊。
- 每次生成 90% 為 2、10% 為 4，位置從空格中均勻隨機挑選。
- 移動時方塊先往該方向壓縮，相同數值依該方向順序合併，再壓縮；每個方塊每回合最多合併一次，新合併出的方塊不會在同回合再次合併。
- 得分為合併後的方塊數值，多組合併則累加。
- 只有盤面真的改變的有效移動，才會生成新方塊、增加步數並更新悔棋紀錄。
- 首次湊出 2048 顯示勝利提示，可選擇繼續挑戰；續玩後不再跳出。
- 盤面無空格且上下左右都沒有相鄰同值方塊時，才判定遊戲結束。

## 操作

| 操作 | 方式 |
| --- | --- |
| 移動 | 方向鍵、`W`/`A`/`S`/`D`、`H`/`J`/`K`/`L`、棋盤上滑動、畫面方向按鈕 |
| 悔棋 | `U` 或「悔棋一步」按鈕 |
| 關閉對話框 | `Esc` |

手勢需要至少 24px 位移，且主要軸向必須明顯大於另一軸（1.25 倍）才算有效；多指觸控或手勢被系統取消時會整個放棄，不會誤判方向。棋盤內不會捲動頁面，棋盤外則維持正常捲動。

## 功能

- 分數、最高分、步數、本局最大方塊。
- 新遊戲（有進度時先確認）、單步悔棋、操作說明。
- 悔棋精確還原上一個有效移動前的盤面、分數、步數與勝負狀態；最高分不倒退，且不可連續悔棋。
- 本局進度、最高分與偏好設定自動保存，重新整理可續玩。
- 外觀：淺色 / 深色 / 跟隨系統。
- 動畫：完整 / 減少 / 跟隨系統（預設尊重 `prefers-reduced-motion`）。
- 清除所有紀錄（操作前確認）。

## 可靠性與可及性

- 存檔讀取前會驗證版本、盤面尺寸、每格數值是否為 2 的次方、分數與步數是否為合理的非負整數，任何一項不符就整份捨棄並提示，不直接信任儲存內容。
- `localStorage` 被停用、寫入失敗或容量不足時，遊戲照常運作，只會提示進度不會被保存。
- 所有功能都能用鍵盤操作；對話框使用原生 `<dialog>` 管理焦點，關閉後焦點回到原按鈕。
- 對話框開啟或焦點在輸入元件時，不會觸發棋盤移動。
- 方塊文字與底色的對比度在淺色與深色主題下皆達 4.5:1 以上（由測試自動檢查），並以邊框輔助區分高階方塊，不單靠顏色。
- 分數與遊戲狀態透過 `aria-live="polite"` 宣告，分數朗讀有節流，不會每次動畫都朗讀。

## 測試

```bash
node tests/run-node.js
```

瀏覽器版（需要透過 http 開啟）：<http://127.0.0.1:8765/game-2048/tests/>

兩者執行同一份 `tests/suite.js`；配色對比度檢查需要讀取 CSS 檔案，僅在 Node 版執行，所以 Node 版比瀏覽器版多一項。

涵蓋範圍包含四方向的壓縮與合併、`2,2,2,2 → 4,4`、`2,2,4 → 4,4`（不會變成 8）、`2,0,2,2 → 4,2`、多組合併的分數累加、無效移動不生成方塊也不覆寫悔棋紀錄、滿盤但仍可合併時不判定結束、勝利與續玩、遊戲結束、悔棋的狀態轉換、存檔還原與各種損壞存檔的拒絕、`localStorage` 不可用與容量不足，以及隨機對局下方塊 id 唯一、不重疊、分數累加一致。
