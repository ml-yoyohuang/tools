# 果實合成

水果掉落、碰撞、同級合成的純網頁遊戲，是 DevToolbox 工具集的一部分。物理由 Matter.js 負責，其餘全部原生實作，不需要後端、帳號或付費服務。**遊戲沒有任何音效或音訊資源。**

目前所有果實都是本地產生的 SVG 假圖，之後可直接替換成正式插畫（見下方「換圖指南」）。

## 啟動方式

請以 http 開啟遊戲與測試頁。在專案根目錄起一個靜態伺服器：

```bash
python -m http.server 8766 --bind 127.0.0.1
```

接著開 <http://127.0.0.1:8766/game-suika/>。

## 部署

整個資料夾就是可部署的靜態網站，複製到任何靜態主機（GitHub Pages、Netlify、Nginx…）即可。所有資源都是相對路徑，放在子目錄也能運作。

## 檔案結構

```
game-suika/
├── index.html
├── css/style.css
├── js/
│   ├── config.js       所有可調參數：等級表、物理、分數、機率、計時
│   ├── world.js        物理世界、合併規則、警戒線判定（不依賴 DOM）
│   ├── images.js       圖片載入與失敗降級（載入器可注入）
│   ├── storage.js      最高分與偏好設定
│   ├── render.js       Canvas 繪圖、合併特效、粒子
│   ├── input.js        Pointer Events、鍵盤
│   └── game.js         組裝層：單一 rAF 迴圈、介面、對話框
├── assets/fruits/      11 張本地假圖（SVG）
├── tools/
│   └── make-dummy-fruits.js   重新產生假圖
├── vendor/matter-js/   matter.min.js + LICENSE（鎖定 0.20.0）
├── tests/
│   ├── suite.js        測試案例（Node 與瀏覽器共用）
│   ├── run-node.js     Node 執行器
```

各層以全域物件串接（`SuikaConfig`、`SuikaWorld`…），不需要打包工具。`config.js`、`world.js`、`storage.js`、`images.js` 同時支援 `module.exports`，所以測試能在 Node 中驅動真實物理。

## 玩法

- 把果實投進容器，兩顆**相同等級**的果實相碰會合成下一級並得分；合成可以連鎖。
- 投放的果實隨機從**前 5 級**挑選，預設等機率。
- **兩顆最高級（大西瓜）相碰時，兩顆一起消除並額外得 100 分，不會產生更高等級。**
- 每次投放後有 480ms 冷卻；冷卻中、暫停中、對話框開啟、遊戲結束期間都不接受投放。
- 已落下的果實頂端**持續**超過警戒線 2 秒才判定結束；剛投放的果實有 800ms 入場寬限（碰到東西即提前結束寬限）。合成產生的果實沒有寬限，不能用來規避判定。
- 切到其他分頁會自動暫停，回來後需手動按「繼續」。暫停時物理、冷卻與危險計時都停住。

### 控制

| 裝置 | 操作 |
| --- | --- |
| 滑鼠 | 移動定位、點擊投放 |
| 鍵盤 | `←` `→` 移動（`Shift` 加速）、`Space` / `Enter` 投放、`P` 暫停、`Esc` 關閉對話框 |
| 觸控 | 按住拖曳定位，放開投放；取消手勢與多指觸控不會重複投放 |

## 換圖指南

1. 準備 11 張圖，覆蓋 `assets/fruits/fruit-01.svg` ～ `fruit-11.svg`（檔名對應等級）。支援透明背景，SVG 或 PNG 都可以。
2. 若要換成別的檔名或格式，改 `js/config.js` 中該等級的 `image` 欄位即可。
3. **碰撞半徑 `radius` 與圖片是分開的**，換圖不需要改任何合併或物理邏輯。顯示大小用 `imageScale`（相對於直徑的倍率）微調，位置用 `imageOffset`（`{x, y}`，邏輯單位）微調。
4. 圖片會自動保持長寬比，並跟隨物理物體的位置與旋轉。
5. 任何一張載入失敗，該等級會自動改畫**色球 + 等級數字**，遊戲照常進行，畫面上會出現一行提示。
6. 想重新產生目前這批假圖：`node tools/make-dummy-fruits.js`。

> 注意：SVG 是嚴格的 XML，同一個元素出現重複屬性（例如兩個 `stroke-width`）會整張解析失敗。

## 參數調整指南

全部集中在 `js/config.js`：

| 區塊 | 用途 | 備註 |
| --- | --- | --- |
| `WORLD` | 邏輯座標、牆壁厚度、地板位置、警戒線高度、出生高度 | 畫面縮放不會改變這些值 |
| `LEVELS[]` | 每一級的名稱、`radius`、`image`、`imageScale`、`imageOffset`、顏色、輔助形狀 | 半徑必須遞增 |
| `SCORING.merge[]` | 合成得分（索引 0 = 等級 1 合成等級 2） | 長度需為等級數 − 1 |
| `SCORING.topClear` | 最高級兩顆相碰的額外分數 | |
| `SPAWN.maxLevel` / `weights[]` | 可投放的等級數與各自權重 | 權重長度需等於 `maxLevel` |
| `PHYSICS` | 重力、彈性、摩擦、阻尼、求解迭代次數、合併後速度上限 | 彈性調高容易彈個不停 |
| `TIMING` | 固定步長、單幀補算上限、投放冷卻、入場寬限、危險判定秒數 | |

目前採用的主要數值：世界 480×780、容器內寬 432、警戒線 y=176、出生高度 y=92；半徑 14→100（11 級）；重力 1.1、彈性 0.08、摩擦 0.34、空氣阻力 0.008、位置/速度迭代各 8；固定步長 1/60 秒、單幀最多補算 3 步；投放冷卻 480ms、入場寬限 800ms、危險判定 2000ms；合成後速度上限 7、沿用來源速度 45%；合成得分 1/3/6/10/15/21/28/36/45/55，最高級消除 100。

## 穩定性設計

- **固定時間步長**搭配單幀補算上限（3 步），低幀率或從背景分頁切回時不會一次補算而爆衝；超過上限直接丟棄積欠時間。
- 碰撞事件只把合併請求**排進佇列**，等物理更新結束後的安全階段才處理。
- 合併前會**再次驗證**兩顆都還存在且未被合併；三顆同級同時接觸時，後續請求會失效，不會重複消耗或重複計分。每顆果實有唯一 ID，同一次更新最多參與一次合併。
- 合成後的新果實在接觸點附近生成，沿用部分來源速度但**設有上限**，且位置會夾在容器內，避免穿牆或爆飛。
- 合併特效與粒子**不參與物理碰撞**。
- 畫面縮放只改變 Canvas 變換矩陣，物理世界永遠使用固定邏輯座標；滑鼠與觸控座標會換算回邏輯座標。
- 視窗尺寸或方向改變時只重算畫面，不會重建或清空進行中的遊戲。
- 重新開始會清掉果實、合併佇列、特效與計時；碰撞事件只在建構時註冊一次，整個頁面只有一個 `requestAnimationFrame` 迴圈。

## 可及性

- 分數、最高分、合成次數、狀態、下一顆預覽都有 Canvas 以外的 HTML 文字版本。
- 所有按鈕都是語意化 HTML，有可辨識名稱、焦點樣式與至少 44px 的觸控高度。
- 對話框使用原生 `<dialog>` 管理焦點，關閉後焦點回到原按鈕；對話框開啟時不接受投放。
- 等級不只用顏色區分：每顆果實與圖鑑都標示等級數字，假圖另有不同的輔助形狀。
- 尊重 `prefers-reduced-motion`（可在「操作說明」中改為完整／減少），減少動畫時關閉粒子與得分提示，物理移動不受影響。

## 實際驗證結果

在瀏覽器中實際操作驗證過：

- 桌機滑鼠定位與點擊投放、鍵盤移動與投放、`P` 暫停與繼續。
- 觸控（Pointer Events）拖曳投放；多指只投放一顆、`pointercancel` 不投放、連點 10 次只產生一顆。
- 連續 45 次點擊投放（含快速連點）共接受 23 次、合成 9 次：**0 次穿牆或掉出容器**，靜止後最大速度 0.004（無持續震動）。
- 遊戲結束流程：果實持續超線後 1993ms 觸發（設定為 2000ms），覆蓋層顯示、焦點移到「再玩一局」、狀態列更新、暫停鈕停用、不再接受投放、最高分寫入。
- 最高級消除：兩顆大西瓜相碰後兩顆都消失、+100 分、不產生更高等級。
- 堆疊崩塌後果實回到警戒線下方，危險計時正確歸零。
- 分頁切到背景自動暫停，回到前景仍維持暫停。
- 視窗縮放與重新計算版面時，進行中的局面（果實數、分數）完整保留；DPR 2 下 Canvas 背景緩衝區為 658×1044，座標換算仍精準對應（畫布中心 → 世界 x=240）。
- 版面：桌機、375×812 手機直向、740×400 手機橫向皆無水平或垂直捲軸，按鈕完整可見。
- 對話框焦點管理與關閉後焦點還原；對話框開啟時 `Space` 不會投放。
- 減少動畫：粒子與得分提示歸零，物理照常。
- 圖片降級：曾有 3 張 SVG 因重複屬性解析失敗，遊戲自動改用色球與等級數字並照常運作（該問題已修正，目前 11/11 正常）。
- Console 全程無錯誤。

**未能實際驗證的項目**：

- 真實觸控裝置與 iOS Safari。這裡是以 Pointer Events 合成事件與行動版視窗模擬驗證，未在實機上測試。
- 以 `file://` 直接開啟。本專案開發時一律透過 http 驗證，`file://` 下各家瀏覽器對本地圖片的限制不一，未逐一確認；若圖片被擋住，遊戲會自動降級成色球與等級數字，物理與合成不受影響。
